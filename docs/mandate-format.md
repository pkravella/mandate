# The mandate format

A mandate is a short-lived contract for one task: what an agent may touch, what
it may do, where data may go, and when it all expires. Anything not granted is
denied.

The schema is the contract — `MandateSchema` in `@mandate-dev/schema` — and it
is `.strict()`, so an unknown key is a parse error rather than a field silently
ignored.

```yaml
mandate: fix-issue-42
task: "Fix issue #42 and open a PR"
requestedBy: user:alice
expiresInMinutes: 30
ceiling: org-policy@v12
grants:
  - action: contents.write
    enforcedBy: proxy
    resources: ["acme/api"]
    branches: ["agent/42-*"]
    paths: ["src/**", "test/**"]
    denyPaths: [".github/workflows/**", "**.env**"]
  - action: pull_request.create
    enforcedBy: proxy
    resources: ["acme/api"]
    branches: ["agent/42-*"]
    base: main
    max: 1
destinations:
  allow: ["github.com/acme/api"]
```

---

## Top-level fields

| Field | Rule | Why |
| --- | --- | --- |
| `mandate` | kebab-case, 1–63 chars | An identifier for logs and the trace header. **Ids can collide**: it is generated by truncating the task at 48 characters on a word boundary, so two tasks opening with the same words share one. `mandateHash` is the real identity and the trace header carries it. |
| `task` | 1–4000 chars | The task as stated. Carried so a reviewer sees what the authority was *for*. It is never parsed for authority, and `validate()` does not read it at all. |
| `requestedBy` | `user:<login>` | The requester, and it must be the person whose authority the mandate is checked against (`--as`), compared case-insensitively — otherwise the mandate is refused as `requester-mismatch`, because the record would name someone whose authority nobody checked. An agent is never a requester: the PRD's lifecycle has context arriving from an authorized source, with an agent's plan admissible as evidence but never as authority. The schema still admits `app:<id>`, and the validator refuses it as `requester-unsupported`: GitHub reveals what another App may do only to that App, so Mandate has no source for an app's authority yet. |
| `expiresInMinutes` | integer, 1–60 | Counted from the session's start, when the token is minted. A GitHub installation token expires one hour from creation and cannot be extended, so a longer mandate is not mintable as a single token, and the PRD's example `expires_in: 2h` is deliberately not expressible. GitHub dates the token from its own clock to the second, so a 60-minute mandate would outlive it by under a second; the session therefore ends 60 s before the token does whenever the mandate would run that late, and the refusal says the credential ended it. |
| `ceiling` | non-empty string | The ceiling this mandate claims to sit inside. **A claim, never a loader argument or a label.** The validator proves containment against the ceiling the *operator* passed; the output, the proof and the trace header name that ceiling by its file and the sha256 of its contents, and show this field only as the mandate's unchecked claim — so a mandate naming `attacker-policy@v1` validates against your ceiling or not at all, and is never reported as having been checked against `attacker-policy@v1`. |
| `grants` | 1–64 entries | Below. |
| `destinations.allow` | list of `host` or `host/path` | Below. |

`notGrantedNotable` from the PRD's example is **rejected**. It is derived from
the catalog for display, and accepting-then-ignoring it would be the worst of
both outcomes — a field that looks load-bearing and is not.

## A grant

```yaml
- action: contents.write      # a catalog operation id
  enforcedBy: proxy           # token | proxy | ruleset | sandbox
  resources: ["acme/api"]     # required, at least one
  branches: ["agent/42-*"]    # optional
  paths: ["src/**"]           # optional
  denyPaths: ["**.env**"]     # optional
  base: main                  # optional
  max: 1                      # optional, 1-100
```

**`action`** must be an id in the operation catalog (about 47 operations). An
unknown one is a parse error naming the field.

**`enforcedBy`** is required, and that is the point. R7 asks for documentation
of "what is enforced where"; making it a schema field rather than prose keeps
the audit log honest about the gap between what a mandate says and what GitHub
can actually refuse. A grant marked `proxy` is *not* enforced by the token, so
it does not survive an agent that goes around the proxy. See
[enforced-where.md](enforced-where.md).

**Which fields a grant may carry depends on the operation.** Each catalog entry
declares what it is `constrainable` by, and a grant carrying a facet the
operation does not support is a parse error — `operation repo.read cannot be
constrained by branches`. `contents.write` is constrainable by resources, paths
and branches; `repo.read` only by resources.

**`max`** is a limit on one session, not a budget for the task: at most that many
calls in this session, counted when the proxy allows one -- so a call that then
fails upstream still spends it, which errs the safe way -- and reset by a new
session. Who can start a new session is the part that matters:

- With `mandate run --sandbox`, serve accepts one connection and ends with it,
  so only the operator can start another, by running again.
- Without it, the agent spawns `mandate serve` from its own MCP config, so the
  agent can reset the count by restarting its MCP server.

Where operations share an MCP tool, `max` is decided by what the call is, as far
as the call says. An `issue_write` create is counted only against
`issue.create`, so `issue.create` with `max: 1` holds even with `issue.update`
granted. The rest cannot be told apart from their arguments -- one `issue_write`
update can label, assign and close at once; one `update_pull_request` can
retitle and close; a pull request comment is an issue comment -- so within
those groups the grants' limits combine: `issue.label` with `max: 5` beside
`issue.assign` with `max: 2` allows seven issue updates of either kind, and the
trace records the first grant that allowed each call.

### The glob language

`resources`, `branches`, `paths`, `denyPaths` and `base` are patterns in a
deliberately tiny language:

| | |
| --- | --- |
| literal characters | match themselves |
| `*` | any run of characters except `/` |
| `**` | any run, including `/` |
| `**/` | zero or more complete segments |

Everything else — `?`, `[`, `]`, `{`, `}`, `!`, `(`, `)`, `|`, `+`, `@`, `\` —
is a **parse error**, not an escape. Containment has to be decidable, and an
undecidable pattern must never reach the point where a decision is expected.
`***` is rejected, and so is any pattern with a `..` segment.

The practical consequence: an ordinary filename can be unrepresentable.
`pages/[id].tsx` contains a glob metacharacter, so it cannot appear in a
pattern. The proxy handles such a path fine as a concrete *value* — the
restriction is on patterns — but a widen offer that would need one is refused
rather than offered, because an offer the CLI would not accept is worse than no
offer: it looks actionable.

### Deny paths are a floor

`denyPaths` subtracts from `paths`. A call is refused if it matches a deny path,
whatever `paths` says, and an undecidable value against a deny list also
refuses — the whole purpose of a deny list is the paths it keeps out.

A widen may never relax `denyPaths`. The widen request type has no field for it,
so it cannot be expressed rather than expressed-and-ignored.

## Destinations

```yaml
destinations:
  allow: ["github.com/acme/api"]
```

Where repository data may go (R9). Each entry is a host, or a host with a path
prefix.

**A bare host covers its subdomains; one with a path does not.** `github.com`
permits `gist.github.com`. `github.com/acme` does not. Matching is on a segment
boundary, so `github.com/acme` permits `github.com/acme/api` but not
`github.com/acme-backup`.

One predicate, `destinationWithin`, decides this for the validator's ceiling
check, the proxy's runtime check and the egress compiler's allowlist, so the
three cannot drift on the same destination.

**Destinations are checked on fields, not on content.** The proxy scans
destination-bearing argument fields — `url`, `clone_url`, `remote`,
`webhook_url`, `fork_owner` and so on. A URL inside a file's `content` or an
issue `body` is **not** a destination, because writing `curl evil.example.com`
into a source file sends nothing anywhere and the bytes still travel to GitHub.
Treating content as a destination would deny any commit touching a
`package.json`, a licence header or a doc with a link in it. A URL written and
*later executed* is a real risk, and it belongs to the sandbox (R9b) and taint
tracking (R14, P1).

## What the lints refuse

Beyond ceiling containment, R4's lints reject a mandate that is technically
inside a loose ceiling and obviously wrong. A lint error is a **rejection**, not
a warning — the point of a ceiling is that it may be loose and still safe.

They catch: a wildcard repository; a wildcard destination; a write that could
reach the default branch; a write with no branch constraint; an operation
classed `forbidden` in the catalog without an explicit ceiling exception;
secret, workflow or actions access; a missing deny list on a write that could
reach sensitive paths; an unbounded count on a side-effecting operation; and an
`enforcedBy` claiming token enforcement for a grant carrying a branch or path
limit the token cannot express.

`fixtures/overgrants/` holds 22 mandates that must each be refused, and
`fixtures/adversarial/` holds 42 written as attacks.

## Validation, in order

1. **Schema.** Shape, field rules, catalog membership, per-operation
   constrainability. A failure here means the mandate never reaches the
   validator.
2. **User authority.** `requestedBy` must name the user whose level is
   checked, and an `app:` requester is refused. Each operation declares a
   `minUserLevel`; the grant is refused unless the requester's real level
   reaches it. Ordinal, no patterns.
3. **Ceiling containment.** Pattern algebra: each facet's glob set must be a
   subset of the matching ceiling clause's. A failure yields the clause id and a
   **counterexample string** the mandate would have permitted.
4. **Cedar cross-check.** Boundary witnesses replayed through `isAuthorized`. A
   Cedar denial of a witness the automata called contained is a validator bug,
   and the mandate is refused.
5. **Destinations.** Every entry must be inside the ceiling's list.
6. **Lints.** Above.

Any doubt is a refusal: an exception, an unparseable pattern, a disagreement
between the two layers, or a mandate too complex to decide within the work
budget. R3's wording is binding — "reject on any doubt."

A mandate that passes all six becomes a `ValidatedMandate`, a branded type whose
constructor is private to the validator. Nothing downstream — the token minter,
the proxy rule compiler, the egress compiler — accepts anything else, so "the
model can never grant itself anything" is a property the compiler checks rather
than one the code review has to.
